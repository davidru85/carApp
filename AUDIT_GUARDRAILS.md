# Specification Audit & Guardrail Definition — carApp MVP

> **Role:** Senior Software Architect / KMP multiplatform system design audit.
> **Objective:** identify every ambiguity, inconsistency and missing definition that would let two competent AI agents produce two incompatible implementations, and propose the precise guardrail that closes it.
> **Audit date:** 2026-08-16 · **Corpus:** `README.md`, `DEFINITION.md`, `SPECIFICATION.md`, `CONTRACTS.md`, `TECHNICAL_PLAN.md`, `DECISION_BOARD.md`, `BACKLOG.md`, `AGENTS.md`, `CONTRIBUTING.md`, `SECURITY.md`, `docs/adr/0000`–`0013`, `docs/templates/agent-handoff.md`, `.github/*`.

---

## 0. Executive summary

The definition package is unusually strong for a greenfield project: scope is closed, decisions are recorded as ADRs, boundaries are stated, and there is a real attempt at a contractual guardrail layer. The failure mode is **not** missing intent — it is that the documents are written in *prose that reads as precise but is not machine-decidable*, and that the precedence order actively promotes the vaguest document over the most precise one.

An AI agent implementing `E1-04` today must invent: the `Result` type, every command model, the `EntityType` enum, the exact integer arithmetic for R-2, and where `ownerId` comes from. Four agents will invent four different answers, and nothing in CI will catch it.

### Blocking issues (must be resolved before Phase 0 closes)

| # | ID | Blocker |
|---|----|---------|
| 1 | `G-01` | Precedence order inverts precision: `SPECIFICATION.md` outranks `CONTRACTS.md`, so vague spec prose legally overrides the exact contract that was written to disambiguate it. |
| 2 | `C-01` | ~20 types are referenced in public interface signatures and **never defined anywhere** (`Result`, `EntitySnapshot`, `EntityType`, `AuthSession`, `NativeAuthCredential`, all `*Command` models, `AppGraph`, `UiState`, …). |
| 3 | `D-01` | Two incompatible field vocabularies (`odometer`/`liters`/`initialOdometer` vs `odometerKm`/`litersScaled`/`initialOdometerKm`) with no declared canonical mapping. |
| 4 | `K-01` | Under the stated dependency rules a repository **cannot obtain `ownerId`** (feature `data` may not depend on `:core:auth`), yet every synchronized row and every Firestore rule requires it. |
| 5 | `K-02` | `:core:sync` must apply remote fuel entries but the "recompute `currentOdometer` transactionally" rule lives in feature `data`, which `:core:sync` may not depend on. Two write paths, one invariant, no owner. |
| 6 | `W-01` | The pull query is defined as `where(updatedAt >= since) … limit(200)` with **no `startAfter` anchor**; `cursor.lastDocumentId` is stored but never used. With >200 documents inside the overlap window the pull loops forever and never converges. |
| 7 | `W-02` | LWW arbitration is specified against `updatedAt` "newer than local" while `CONTRACTS.md` forbids local `updatedAt` from being authoritative; and the "lexical `id` tie-breaker" is meaningless for a single document (both sides share the id). |
| 8 | `D-02` | `LOCAL_OWNER` → real UID migration is named but never defined. Phase 1 enqueues outbox rows stamped `LOCAL_OWNER`; at Phase 2 every one of them is rejected by the Firestore rules and becomes `FAILED_POISONED`. Silent data loss path. |
| 9 | `W-03` | "100% of MVP functionality usable without network" (P2, NFR) directly contradicts "MVP first launch requires network connectivity to establish an anonymous Firebase UID" (`CONTRACTS.md §11`). |
| 10 | `D-03` | R-2's canonical formula hard-codes `* 100` (EUR) in `SPECIFICATION.md`, and `CONTRACTS.md`'s `minorUnitFactor` version, implemented literally in integer arithmetic, truncates before it rounds. Both are wrong as written. |
| 11 | `C-02`/`K-09` | Kotlin `value class` identifiers (`EntityId`, `OwnerId`, `CurrencyCode`, `FuelVolume`, `PricePerLiter`) and a generic `Result<T, E>` sit on the Swift-facing surface; inline value classes do not survive the Objective-C export and generic hierarchies export poorly even with SKIE. |
| 12 | `S-01` | Firestore **region/location** and Firebase **project topology** (dev/staging/prod) are undecided. Firestore location is immutable after creation and the user base is Spanish — this is a one-way door being left to an agent. |
| 13 | `G-02` | Five `DECISION_BOARD.md` items are `Pending` (logging impl, flow testing, localization, architecture-check library, crash reporting) while stories that depend on them (`E0-03`, `E0-04`, `E0-05`) are supposedly Ready. The project violates its own Definition of Ready at Phase 0. |

### Severity legend

`BLOCKER` — will produce divergent or incorrect implementations, or an irreversible decision.
`HIGH` — will produce rework, silent data loss, or an unenforceable rule.
`MED` — will produce inconsistency between agents but is cheap to correct later.
`LOW` — editorial or hygiene.

## 2. KMP architecture

| :--- | :--- | :--- |
| `K-01` · **BLOCKER** · `TECHNICAL_PLAN.md §4` vs `CONTRACTS.md §3`, `§12`, `§16` | Feature `data` is allowed to depend only on its own `domain`, `:core:database` and `:core:sync` — **not** `:core:auth`. Yet every synchronized row and every remote document requires `ownerId`, and `VehicleRepository.createVehicle(command)` has no owner parameter. ## Appendix A — Normative language block (paste into `AGENTS.md` and `CONTRACTS.md`)

```markdown
## Normative language

The key words MUST, MUST NOT, REQUIRED, SHALL, SHOULD, SHOULD NOT, MAY and OPTIONAL
are to be interpreted as described in RFC 2119.

- MUST / MUST NOT — enforced. A violation fails CI or blocks review. An agent that
  cannot satisfy a MUST stops and escalates; it does not work around it.
- SHOULD / SHOULD NOT — a deviation is permitted only if it is stated explicitly in
  the agent handoff under "Decisions Made", with the reason.
- MAY — free choice; the choice does not need to be reported.

Any normative sentence in this repository that uses a bare present tense ("the app
warns the user", "IDs are UUID v4") has the force of MUST.
```
