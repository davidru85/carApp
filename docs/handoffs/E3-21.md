# Agent Handoff - E3-21

## Story

`E3-21 - Explicit Startup Reset of Stale SYNCING Rows - S` (`docs/BACKLOG.md`), the second story of
bundle `E3-B1` (`D-205`, ADR-0206). The bundle's live checkpoint is `docs/handoffs/E3-B1.md`.

## Ready Check

- Backlog story: `E3-21` (`docs/BACKLOG.md`, story section and index row).
- Acceptance criteria reviewed:
  - a startup statement resets every `SYNCING` entity row without a resolved push to a state
    consistent with its outbox row, in one transaction;
  - a test seeds a `SYNCING` entity row and asserts the reset after app start;
  - the change keeps the aggregate `SyncStatus` derived from the outbox and does not alter push
    ordering.
- Dependencies checked: `E3-03` (the engine and the `SYNCING` transient), `E3-07` (the `D-194`
  count-gated startup execution policy) and `E3-13` (the single `EntityType` source, merged into this
  branch) are complete.
- Decisions checked: `D-207` (ADR-0208) is `Accepted`: a stale row returns to `FAILED_RETRYABLE` when
  its outbox `lastErrorCode` is non-null and not a connectivity code, and to `PENDING` otherwise; once
  per app start, under the cycle's serialization, count-gated, one transaction, failure reported once
  and not retried. Applies `D-194`, `D-38`, `D-190` and `D-172`. No dependent decision is open.
- Normative sections reviewed: `docs/CONTRACTS.md §7` (state machine, transition table, the
  `SYNCING` transient paragraph), `§9.3`, `§9.7`, `§9.9`, `§8` (the purge execution policy);
  `docs/TECHNICAL_PLAN.md §6`; `docs/SPECIFICATION.md §11`.
- Placement, derived from the code: the controller holds `cycleMutex` only for admission and runs
  one cycle at a time (`cycleRunning`), so "under the cycle's serialization" is satisfied by running
  the reset as the first step of the controller's first executed cycle, before the offline and
  `LOCAL_OWNER` refusals. `OwnerRecoveryGate` calls `sync(OwnerChanged)` whenever the owner resolves
  to a real identity at startup, online or not, and a `LOCAL_OWNER` row is never marked `SYNCING`.
- Expected verification: database tests for the classification, the untouched outbox and the
  rollback; Android and iOS file-backed write-lock tests for the count gate; controller tests for the
  ordering, the once-per-controller latch, the offline case and the failure policy; an app-graph test
  for the startup reset; `ConnectivityCodeParityTest` over the new statements; the complete
  `AGENTS.md` command.
- Human review gates identified before work: gated paths `core/database/**`, `core/sync/**` and
  `docs/CONTRACTS.md`; gated topic "the synchronization algorithm or its state machine"; the story is
  marked "Human review required".
- Rule 0 acknowledged: chat replies for this story are in Spanish (es-ES) and every artifact it
  produces is in technical English.
