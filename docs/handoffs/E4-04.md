### Store privacy drafts (for the owner, O9 and O10; not legal advice)

Code facts used:

- Firebase Auth UID keys every backup document (`users/{uid}/…`, `docs/CONTRACTS.md §16`).
- Google sign-in stores the Google account's name and email in Firebase Auth; the Apple request asks
  for no scope, so Apple supplies no email or name (`iosApp/NativeSignIn.swift`).
- Backed-up content: vehicles (name, brand, model, fuel type, initial odometer) and refuels (date,
  odometer, litres, price per litre, total cost, currency, full tank, missed entries, notes)
  (`docs/CONTRACTS.md §16`).
- Analytics is off by default and starts only after the Settings opt-in; it is pseudonymous (SDK app
  instance ID, no user ID, no AAID/IDFA/IDFV, no personalised ad signals) (`docs/CONTRACTS.md §16.1`,
  `D-203`).
- Crash collection follows the same opt-in and never carries the UID or user content (B2-D4,
  `docs/CONTRACTS.md §20.3.1`, `docs/SECURITY.md`).
- All traffic goes to Google Firebase over TLS. No advertising, no data sale, no third-party sharing
  beyond Google acting as service provider.
- In-app account deletion deletes remote data, then the Auth account (`D-23`), and revokes Sign in with
  Apple revocation is deferred to `E4-09` by `D-236`; a web request page exists (O10).
- No location, contacts, photos, files, health, messages, calendar, browsing or installed-apps access.
