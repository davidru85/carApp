### 2026-10-15 — E3-20 review correction R1 (PR #88)

- Date: 2026-10-15. Branch and base: `story/E3-B1-client-sync-hardening` from `main` at `c397b4c5`.
- Finding: **R1 [P2]** — `UntypedFields.ios.kt` coerced a non-string Firestore map key with
  `(key as? String ?: key?.toString().orEmpty())`, so `FirebaseRemoteSyncSource.toJsonElement()`
  received a string-keyed map and could not recognize the unsupported original shape. The `D-208`
  marker was therefore absent and the quarantined payload lost the representation `§20.7` requires.
- Governed by the existing accepted decision: `D-208` (ADR-0209) and `docs/CONTRACTS.md §9.5` require
  a map whose keys are not all strings to become one `{UNSUPPORTED_PROVIDER_VALUE_KEY:
  NON_STRING_KEY_MAP}` marker, independently of the map's position. No iOS exception exists, so this
  correction applies the decision literally and introduces no new product policy and no new decision
  ID. The sentence in `docs/handoffs/E3-20.md` retaining iOS key coercion is removed.
